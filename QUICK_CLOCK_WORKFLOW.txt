                        KEY DIFFERENCES FROM NORMAL LOGIN
═══════════════════════════════════════════════════════════════════════════════

NORMAL LOGIN (Sign In Button)          QUICK CLOCK (Scan Face Button)
─────────────────────────────────      ─────────────────────────────
1. Enter ID manually                   1. Face is auto-recognized
2. Enter password manually             2. No password needed
3. User creates session                3. No session created
4. Access full dashboard               4. Attendance recorded only
5. Must manually clock in/out          5. Clocking happens immediately
6. Takes ~20-30 seconds                6. Takes ~5-10 seconds
7. Multiple login options available    7. Face only (no fallback)


═══════════════════════════════════════════════════════════════════════════════
                            DATABASE CHANGES
═══════════════════════════════════════════════════════════════════════════════

✓ No schema changes required
✓ Uses existing tables:
  • attendance (employee_id, clock_in, clock_out, verification_method)
  • audit_logs (entity_type, entity_id, changed_by, reason)
  • employees (id, name)
  • users (username)

✓ Fills same fields as normal login:
  • INSERT into attendance(employee_id, attendance_date, clock_in, verification_method)
  • UPDATE attendance set clock_out = NOW() WHERE id = record_id
  • INSERT into audit_logs(..., reason = "Face-scan clock from login screen")

✓ Dependent calculations auto-trigger:
  • late_minutes
  • early_leave_minutes
  • overtime_minutes
  • actual_minutes
  (These are computed by compute_attendance() on every change)
